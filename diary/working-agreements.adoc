== Working agreements that emerged

None of these were agreed up front. Each one came out of something going wrong.

* *One issue, one branch, one PR, rebase merges only.*

* *One commit per slice of a request, with the "why" in the body.* These commit
  messages are the primary record and are written to be read later — the diff
  says what changed and only the message can say why it was worth changing.

* *AI-authored architecture content stays `proposed` / `reviewed: false` until
  a human reviews it.* Marking one's own homework is not review.

* *Every dependency justifies itself against this project* — not against a
  reference stack, and not against another project it was borrowed from.

* *Every guard gets broken on purpose before it is trusted.* See the
  through-line; this is the rule the other six lessons collapse into.

* *Caveats need an ask.* Listing a concern that requires no action from the
  reader is noise. This was rightly called out, and the test is simple: if the
  reader cannot do anything with it, it is not a caveat, it is throat-clearing.

* *A claim in an issue or PR outlives the code it justified.* When a
  justification turns out to be wrong, the issue gets corrected too — not only
  the code.

* *A document gets read against itself before it is published.* Four review
  findings in one day were a rule stated in one paragraph and contradicted in
  another paragraph of the same file — each half defensible alone. The pass that
  catches this needs no tooling, only a reader who did not just write the text.
  Its companion: a rule generalised from the example in front of you is right for
  that example and usually wrong for the next one.

* *A document that is open is not the document that decides.* Chapter 8's
  bulleted list gave the aggregates; ADR-009's aggregate map decided them, and
  they disagreed. The list was being replaced by the same pull request that read
  it. Before asserting a structural fact, open the artifact that owns it.

* *A rule about code says when it starts binding.* ADR-022 rule 3 was written as
  a description of a state nobody had established, so the commit implementing it
  would have violated it. A rule that is not true yet is staged, with the
  exception named and an issue that ends the staging — or it is not merged.

* *A term nobody was asked is not agreed.* Twelve terms were put to the owner
  one at a time and were his; the rest arrived in a bulk table and one of them
  was wrong. The batching step is where an agreement pass stops being one.

=== On the collaboration itself

Two corrections shaped how the work is done more than any technical decision
did.

*Ask one question at a time.* A batch of three grilling questions is an
interrogation. The answers collide, and the least important question tends to
attract the most attention.

*Ceremony is a cost, not a virtue.* Filing an issue to describe a request that
was just made, or publishing a report that carries no signal a red pull request
does not, adds process without adding information. The stop test we apply:
without it, would a later reader probably decide wrongly or miss an important
assumption? If not, it does not get built.
