= Feature development

Building the budget the owner uses: the master data, the views, and the numbers
they show.

*Status:* on ice since 2026-07-29 — the domain model turned out to be a level
short, and building on it would have produced more code answering the wrong
question. #68 has since settled the terms; what the resumption still waits on is
#76 and #79 carrying them into the documentation and the code. Defects in what is
already shipped are fixed while the topic is on ice — #82 was one — because the
owner is using it.

== Where we are

The backend has `Transaction`, `Category`, `CategoryGroup`, `FixedCost`, `Money`,
`PaymentInterval` and `TransactionType` under `domain/model/`, with
`MonthlyExpenditureCalculator` in `domain/service/`. The web client has three
features: `transactions`, `categories`, `monthly-expenditure`.

`MonthlyExpenditureCalculator` sums the expense transactions of the current
calendar month. The number the product needs is a long-run average over the
tracking window. Everything about it passes — tests, ArchUnit, coverage — because
no check can ask whether the right quantity is being computed. That is #62, and
it is the origin of the "wrong question" category in the through-line.

`Category` and `CategoryGroup` are addressed by a name in the query string rather
than in a path segment, because a name may contain a slash and Tomcat rejects the
percent-encoded form in a path. The web adapter now has one test that runs over a
real connector, `NameWithSlashTest`; every other controller test is `@WebMvcTest`
and cannot see this class of defect at all.

== Open in this topic

`FixedCost` carries `anchorDate`, a term ADR-022 rejects. The rename is tracked
in `progress/domain-model.adoc`, because it is a language change rather than
feature work — but it lands in this code.

Nothing here is blocked on a decision that has not been taken. It is on ice by
choice, not by obstacle.
