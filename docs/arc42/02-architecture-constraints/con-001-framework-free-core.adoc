[[con-001-framework-free-core]]
== CON-001: Framework-Free Core

No class under `eu.dieterbaier.budget.domain` or `eu.dieterbaier.budget.application`
may depend on Spring, Jakarta, Hibernate, or Jackson, and none may carry a Spring
or Jakarta annotation.

[cols="2,3", options="header"]
|===
| Rule | Enforces
| The core has no compile-time framework dependency | xref:adr-012-explicit-bean-configuration[ADR-012]
| The core carries no framework annotations | xref:adr-012-explicit-bean-configuration[ADR-012]
|===

The second rule overlaps the first, because an annotation is also a dependency.
It is kept separate because it is the one that fails most clearly for the mistake
ADR-012 actually anticipates: a `@Service` landing on an application service,
after which `@Transactional` and field injection become the natural next step.

Hibernate and Jackson are listed alongside the two frameworks ADR-012 names.
Neither is a decision in its own right; they are the dependencies that usually
arrive next, smuggled in by a persistence or serialization convenience on a
domain type.
