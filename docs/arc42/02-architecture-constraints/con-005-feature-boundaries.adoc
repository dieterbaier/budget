[[con-005-feature-boundaries]]
== CON-005: Feature Boundaries

A feature owns its interior. Other features see only what its `index.ts`
exports, shared code knows nothing about features, and the graph between
features has no cycles.

[cols="2,3", options="header"]
|===
| Rule | Enforces
| A feature is imported only through its public API | xref:adr-014-frontend-architecture-style-and-stack[ADR-014]
| Dependencies point inward: app to features to shared | xref:adr-014-frontend-architecture-style-and-stack[ADR-014]
| Shared UI imports no feature, API, or query module | xref:adr-014-frontend-architecture-style-and-stack[ADR-014]
| The feature graph is acyclic | xref:adr-014-frontend-architecture-style-and-stack[ADR-014]
|===

`src/main.tsx` is the entry point and belongs to no element. It mounts the app
shell and nothing else, so the element rules ignore it rather than inventing a
layer to hold it — the same treatment `BudgetApplication` receives in
xref:con-002-hexagonal-boundaries[CON-002].

`src/app` is the composition root, and it is the only place allowed to know
every feature at once: it mounts the providers and, once
xref:adr-014-frontend-architecture-style-and-stack[ADR-014]'s router trigger
fires, the routes. That privilege is deliberately narrow — it reaches features
through the same public API everyone else uses, so being the composition root
buys it breadth, not depth.

The presentational rule is the part of Atomic Design that survived ADR-014, and
it is stated as a dependency rule rather than as a naming convention on purpose:
"this component fetches nothing" is checkable, whereas "this component is a
molecule" is not.

Each rule was verified by writing the violation it forbids and watching the
build fail, not by observing a clean run. That distinction earned its keep: the
cycle rule initially reported nothing at all, because without
`settings['import/parsers']` it cannot parse the TypeScript modules it follows,
finds no exports in them, and concludes there is no cycle. It passed because it
was blind. A fitness function that cannot see is worse than none, since it also
removes the suspicion that would have caught the gap.

The cycle rule is also the one whose message does not name this constraint —
`import/no-cycle` accepts no custom message and reports only "Dependency cycle
detected". The other three name CON-005 and ADR-014 in their output.

Checked by `application/web/eslint.config.js`.
