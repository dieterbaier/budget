[[con-008-web-client-payload-budget]]
== CON-008: Web Client Payload Budget

`npm run build` measures the gzipped application bundle after `vite build` and
exits non-zero above the budget. That is the command the `web` job of
`PR validation` already runs, so the budget gates integration without a separate
step — the same arrangement as
xref:con-006-backend-test-coverage[CON-006] and
xref:con-005-feature-boundaries[CON-005].

[cols="2,1,2", options="header"]
|===
| Measured | Budget | Enforces
| `dist/assets/*.js`, gzipped | 92 kB | xref:qs-003-web-client-payload[QS-003]
| `dist/*.js` — service worker and Workbox runtime | 10 kB | xref:qs-003-web-client-payload[QS-003]
|===

Two ceilings rather than one so that feature work cannot consume the tooling
allowance and plugin churn cannot consume the application allowance. The
application bundle is 88.8 kB and the runtime 6.0 kB.

=== How it was verified

The first version of this check was verified by lowering the budget to 50 kB and
watching the build fail. That proved the script could reject *something*. It did
not prove the property the decision claimed — that the budget preserves the Zod
Mini choice — and the property turned out to be false: reverting to the full Zod
build measures 74.0 kB, which the original 75 kB ceiling accepted.

The ceiling was then 70 kB, and the verification was the regression itself: with
the full build restored the check reported 74.0 kB against 70 kB and exited
non-zero. That is the difference between testing the mechanism and testing the
claim.

The ceiling is now 92 kB, raised for the router adoption in issue #8, and that
verification no longer holds — above 74 kB the full Zod build passes. QS-003
records why the raise was accepted and what it gave up. The check has since
rejected something real, though: it failed the categories feature at 88.8 kB
against 70, which is what forced the decision instead of letting the growth
through unnoticed.

Its failure message says what to do about it: make the bundle smaller, or change
the budget *as a decision*, with the number that justifies it recorded in QS-003.
Raising a budget to make a build pass is the failure mode this constraint exists
to make visible, and no tool can prevent it — only make it deliberate.

Checked by `application/web/scripts/check-bundle-budget.mjs`.
