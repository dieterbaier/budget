== CON-003: Persistence Isolation

The JPA entities are a storage detail. What crosses a port is the domain model.

[cols="2,3", options="header"]
|===
| Rule | Enforces
| JPA entities live only in the persistence adapter | xref:adr-009-domain-identity-and-ddd[ADR-009]
| Spring Data repositories live only in the persistence adapter | xref:adr-006-relational-datastore[ADR-006]
| JPA entities do not escape the persistence adapter | xref:adr-009-domain-identity-and-ddd[ADR-009]
|===

The third rule is not implied by the layer direction of
xref:con-002-hexagonal-boundaries[CON-002]. A controller returning a JPA entity
is one adapter reaching into another, which the layer rule permits — this is the
rule that catches it, and with it the surrogate key leaking into the API.

=== Deliberate Exception

`LocalDataSeeder` writes entities directly through the JPA repositories. It runs
only under the `local` profile to make `./gradlew bootRun` return real numbers,
and never appears in a request path, so it is excluded rather than forced through
the ports.
