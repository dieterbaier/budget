== QS-003: Web Client Payload Budget

=== Scenario

[cols="1,3", options="header"]
|===
| Element | Description
| Source | A developer adding a feature or a dependency to the web client.
| Stimulus | The change increases the JavaScript the browser must download.
| Artifact | The web client's application bundle in `dist/assets`.
| Environment | A production build, `npm run build`, as run locally and by the `web` job of PR validation.
| Response | The build reports each bundle's gzipped size against its budget, and fails when either is exceeded.
| Response Measure | The application bundle stays at or below *70 kB gzipped*, and the PWA runtime at or below *10 kB gzipped*. When this scenario was written they were 61.2 kB and 6.0 kB — roughly 13% and 40% headroom.
|===

=== Two ceilings, because the two grow for different reasons

The *application* bundle is what this project's own decisions move:
xref:adr-016-frontend-response-validation[ADR-016] chose Zod Mini over the full
build and took 13.7 kB out of it.

The *PWA runtime* — the service worker and Workbox code that `vite-plugin-pwa`
generates — moves when the plugin is upgraded, not when a feature is written.

They are budgeted separately rather than together so that feature work cannot
consume the tooling allowance and plugin churn cannot consume the application
allowance. An earlier version of this scenario reported the runtime without
bounding it, which left it free to grow to any size: a printed line is not a
gate, and nobody reads build output looking for a number that has not failed.

=== On the numbers

The application ceiling is 70 kB rather than a rounder 75 because *the regression
it claims to prevent has to fail it*. Reverting to the full Zod build measures
74.0 kB gzipped. At 75 kB that passes — the budget would have quietly permitted
exactly the change ADR-016 decided against. At 70 kB it fails, with 13% headroom
left for legitimate growth.

That was found by applying the regression and running the gate, not by reasoning
about the numbers: proving the check can reject *something* is not the same as
proving it protects the property it claims to.

The PWA ceiling of 10 kB is deliberately generous against a current 6.0 kB. It
exists to catch a gross regression from a plugin upgrade, not to police normal
variation.

Raising either is allowed and is a decision: it needs the number that justifies
it, recorded here. Raising one to make a build pass is not.
