= Building Block View

[plantuml,budget-building-blocks,png]

[cols="1,2,2,2", options="header"]
|===
| Building block | Responsibility | Interface | Storage location
| Web PWA | Entry forms and budget/pension views | Backend API | `application/web`
| HTTP Adapter | API boundary, auth, validation | Calls inbound use-case ports | `application/backend/.../adapter/in/web`
| Use-case ports | Inbound application boundary | Interfaces implemented by services | `application/backend/.../application/port/in`
| Application Service | Use-case orchestration | Implements inbound ports, depends on outbound ports | `application/backend/.../application/service`
| Budget Domain | Money rules and calculations | Domain services | `application/backend/.../domain`
| Repository ports | Outbound persistence boundary | Interfaces implemented by adapters | `application/backend/.../application/port/out`
| Persistence Adapter | Repository implementations | Implements outbound ports | `application/backend/.../adapter/out/persistence`
| PostgreSQL | Persistent records | SQL | Managed database
|===

Two port seams keep the core isolated. The HTTP adapter depends on an *inbound
use-case port* that the application service implements; the application service
depends on *outbound repository ports* that the persistence adapter implements.
The domain depends on nothing outward. Every interaction with an infrastructure
component (HTTP in, database out) therefore crosses a port implemented by an
adapter, which keeps the money rules testable in isolation and the datastore
swappable.
