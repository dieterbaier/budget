== ADR-011: No Lombok

=== Status

Accepted. Confirmed by the owner on 2026-07-24.

=== Decision

The backend does not use Lombok. Value objects and DTOs are Java `record`s;
entities use plain, explicit constructors and accessors.

=== Decision Drivers

* The owner prefers not to use Lombok.
* Java 21 `record`s already remove most boilerplate for value objects and DTOs.
* Avoid a compile-time annotation processor / agent and its IDE-plugin coupling.

=== Considered Options

==== Plain Java with records (chosen)

No extra tooling; records cover value objects and DTOs; entities are explicit.

==== Lombok

Less entity boilerplate, but adds an annotation processor and agent, an IDE
plugin dependency, and hidden generated code — cost the owner does not want for a
codebase this size.

=== Consequences

==== Positive

* No annotation-processor/agent; the code is exactly what you read.

==== Negative

* Slightly more boilerplate in JPA entities (constructors/getters), accepted as
  a fair trade.
