== ADR-003: Server-Owned Budget Calculation

=== Status

Accepted. Confirmed by the owner on 2026-07-24.

=== Decision

All calculations — monthly expenditure and the overspending signal, fixed-cost
amortization, account-reserve requirements, cash runway to month end, and the
pension projection — live in the backend domain layer. The PWA renders results;
it does not compute them.

=== Context

The rules are the heart of the product and must be covered by TDD and Gherkin
features. Concentrating them in the hexagonal domain keeps one tested source of
truth and keeps the client thin. There is one user, so there is no need to push
computation to the client for scale.

=== Considered Options

==== Server-owned (domain layer)

One implementation, fully testable behind the application boundary.

==== Client-owned

Duplicates money rules in TypeScript and undermines the TDD/Gherkin approach.

==== Database views only

Buries rules in SQL where they are hard to unit-test and evolve.

=== Consequences

* Money rules have one implementation point, exercised by domain tests.
* Live views depend on backend availability (acceptable for a single user).
