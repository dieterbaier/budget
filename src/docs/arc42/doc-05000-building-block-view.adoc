= Building Block View

[plantuml,budget-building-blocks,png]
----
@startuml
!include <C4/C4_Component>
Container(web, "Web PWA", "React + TypeScript", "Transaction entry, budget and pension views")
Container(api, "HTTP Adapter", "Spring MVC", "Versioned JSON API, single-user auth, validation")
Container(app, "Application Layer", "Use-case ports", "Orchestrates domain use cases")
Container(domain, "Budget Domain", "Framework-free Java", "Money rules: expenditure, reserves, pension")
Container(persistence, "Persistence Adapter", "Spring Data JPA", "Implements repository ports")
ContainerDb(db, "PostgreSQL", "SQL", "Accounts, groups, categories, transactions, fixed costs, income, balances")
Rel(web, api, "Uses", "HTTPS/JSON")
Rel(api, app, "Calls")
Rel(app, domain, "Invokes")
Rel(app, persistence, "Uses port")
Rel(persistence, db, "Reads/writes")
@enduml
----

[cols="1,2,2,2", options="header"]
|===
| Building block | Responsibility | Interface | Storage location
| Web PWA | Entry forms and budget/pension views | Backend API | `/web`
| HTTP Adapter | API boundary, auth, validation | HTTP JSON | `/backend/.../adapter/web`
| Application Layer | Use-case orchestration | Ports | `/backend/.../application`
| Budget Domain | Money rules and calculations | Domain services | `/backend/.../domain`
| Persistence Adapter | Repository implementations | JPA | `/backend/.../adapter/persistence`
| PostgreSQL | Persistent records | SQL | Managed database
|===

The domain depends on nothing outward; the HTTP and persistence adapters depend
inward on application ports. This keeps the money rules testable in isolation and
the datastore swappable.
